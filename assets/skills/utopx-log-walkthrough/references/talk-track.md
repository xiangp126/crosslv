# Presenter talk track

Written only when Peter asks how to present a page. Deliver it in Chinese in the reply (not on
the page and not in a file unless asked), with identifiers, log lines and commands untranslated.
Every fact in it comes from the page or the log; nothing new is claimed.

## Structure

1. **Opening, two or three sentences**: what the feature is in one sentence, what this run is
   (box, FW, seed, result), what the audience will see.
2. **How to read the page, one minute**: the stage on top (host functions left, device right,
   a request travels right, the reply comes back), the step's log lines below it with numbered
   notes under the line they explain, the run map with one tick per command, the transport and
   keyboard (arrow keys, space).
3. **The whole run first**: the run map, flow by flow, with the counts from the summary (how
   many commands, which function works when).
4. **Flow by flow**: for each flow, which step to stop on, what to point at on the stage, which
   marked line to show, and the one sentence to say. Skip steps that only repeat a pattern.
5. **The failure, if the run failed**: the failure step, the first FATAL and what utopx dropped
   before it.
6. **Closing**: the statements table, what the run shows, what it cannot show and why.
7. **Likely questions**, each with its answer and the step or line that shows it.
8. **A five-minute version**: the five steps to stop on, one sentence each.
