# 两份真实文档的解剖

这个文体不是设计出来的,是在互不相干的任务里**各自独立长出来**的。
下面是解剖 —— 规模、形态、关键片段都摘在这里,不必去找原件。

两份都写了同一条铁律(实时更新 + 旧结论不删),措辞不同但意思一样 —— 这是本 skill 存在的理由。

第三种形态(线性推进、有里程碑的项目)不另举例:`templates/TRACKING.md` 的骨架本身就是它 ——
`S0..Sn` 的状态看板当全文索引,加一条可判定的达标定义。

---

## 例一:多对象台账 — `OCI_EMU/TRACKING.md`

> 原名 `branch_propagation_ledger.md`,2026-09-18 改为固定名。
> **名字比内容窄**是改名的原因:它最后记的远不止分支传播,还有归属裁决、CI 史、
> 评审过程、方法论教训。这正是本 skill 规定文件名固定的由来。

**规模**:约 5700 行,133 张表,212 个标题。
**形态**:N 个 commit × M 条分支的传播台账。

**它长这样**:

- 开头:用途 → 建档日期 + `持续更新,不另起新文件` → 读者假设 → **书写约定** →
  常量区 → `## ⚠ 更新纪律 —— 不要等人提醒` + 七类事件表
- `# ★ 总账(按分支)`:①②③④ 每条分支一节,节内 ACTIVE 置顶、作废折叠
- `## 1.x` 规程与硬规则(用插入式编号 `1.5` / `1.6`)
- `## 3 – 4.27` 逐事件记录,**标题即结论句**:
  `## 4.14 <作业号> 再挂同一处 —— 归因:**非我方**,但分支级阻塞(0805)`
- `## 7 / 7bis / 7ter / 7quater / 7quinquies / 7sexies / 7septies / 7octies` —— 拉丁序数续写,
  就是为了不重排已发布的编号

**值得抄的三处**:

1. **状态列当微型叙事**。主表的状态格可以有几千字符,用 `·` 串起票数、PS、SHA、CI 号、
   session id、注意事项。不要为了"整洁"把它拆成多列 —— 拆了就要跨列对照,更难读。
2. **对齐核对表声明"实证,不是从上表抄的"**。矩阵表如果抄主表,就会跟着主表一起错;
   标题里写死判据,逼自己每次重新查。
3. **撤回声明块**(§J1)。它不只是改结论,还**冻结该结论的对外使用**:
   "在拿到进一步实证之前,不要把X用于任何对外答复。"

**反面教材**:文件名。见本节开头。

## 例二:递增编号问题日志 — `OCI_EMU/bf4_bringup_log.md`

**规模**:约 1450 行,32 条问题。
**形态**:环境 bring-up,问题一个接一个冒出来。

**记录约定逐字**:

```markdown
**记录约定**:遇到一个问题当刻追加一条,解决后就地更新该条(不另起文件、不删旧结论)。
每条包含:现象 / 定位 / 处置 / 结果。脚本层面的修复一律改进脚本本身,不用手工命令绕过。
```

**条目形态**:`## #1 芯片被误标为 ARGAMAN,实为 BRONCO ✅ 已解决`,
状态后缀有 `✅ 已解决` / `🔴 待处置` / `⚠ 我先前的结论是错的`。

**值得抄的两处**:

1. **四段式**(现象 / 定位 / 处置 / 结果)缺一段就是没查清。现象要**逐字贴原文**,不要转述。
2. **`## #14` `#24` `#30/#31` 是就地推翻前条的更正** —— 编号不回收,
   新条目明写"推翻 #N",旧条目保留。

## 另外两份值得看的

**`OCI_EMU/mars_regression_delegation_gap.md`**(约 2200 行)
—— 分析型文档长期化的样本。它的四元头值得抄:

```markdown
**日期**:… **触发**:… **结论**:… **方法**:…
```

以及溢出编号的另一种写法:`## 16.4b ~~<原标题>~~ ← 已推翻,见 §16.4c` → `## 16.4c 【更正后】…`
→ `## 16.4d 【定案】…`。

**`5257991_dbcq_cap/ROOTCAUSE_AND_FIX.md`**(约 1000 行)
—— 开篇第一节就是 `## 0. ⚠ 先读这段:本文有三处结论已被后续调查推翻`。
**把勘误放在最前面**,而不是散在各节里等人撞上。文档越长这一招越值钱。

## 三份文档共同的"人格"

1. **只增不删** —— 错的结论打删除线留在原位,配「当初为何走错」+「下次的判据」。
2. **每个结论都要能指到一条对照** —— 表里留对照行,否则不下结论句。

这两条不是风格偏好。它们是这类文档**唯一**比聊天记录更有价值的地方:
聊天记录也能记下做了什么,但只有这里会记下**什么被排除了、为什么**。
